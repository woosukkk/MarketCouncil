# 기업별 공시·IR 원문 준비와 분석 gate

관련 작업: [GitHub #29](https://github.com/woosukkk/MarketCouncil/issues/29).
대상은 삼성전자, SK하이닉스, 현대자동차, NAVER, Apple, Microsoft의 지정된 대표 상장 종목이다.

## 자료 흐름

1. DART/SEC에서 기업 식별자와 현재 요청한 정기 공시 목록을 확인한다.
2. 원본과 추출 본문을 기업별 로컬 폴더에 저장한다. 공식 IR 사이트에서 실적 발표 본문도 수집한다.
3. 경로, 크기, 원본/본문 SHA-256, 기업, 공식 출처, 발표일과 보고 기간을 재검사한다. 제목 목록·검색 요약·오류 페이지는 본문으로 인정하지 않는다.
4. 최신 필수 자료의 수집·검증에 실패하면 과거 캐시로 준비 완료를 대체하지 않는다.
5. 최소 조건이 충족된 경우에만 유료 분류·분석·토론을 시작한다. 검증한 원문의 제한된 발췌를 공통 근거에 넣는다.
6. 결과와 출처/날짜/해시 보고서를 저장한다. 원문 파일과 로컬 경로는 이 보고서에 포함하지 않는다.

## 최소 조건과 한계

| 항목 | 조건 |
| --- | --- |
| 연간 보고서 | 보고 기간과 발표일이 기준일로부터 550일 이내 |
| 최근 재무 자료 | 200일 이내 분기/반기 자료 또는 보고 기간 200일·발표일 120일 이내의 연간 자료 |
| 실적 발표 | 보고 기간과 발표일이 200일 이내 |
| 본문 | 연간/중간 보고서는 공백 제외 1,000자 이상, 실적 발표는 800자 이상 |
| 중복·무결성 | 원본과 추출 본문 해시 재확인, URL·본문 해시·문서 ID 중복 제외 |

이 기준은 자료 확보의 운영 조건이다. 회계 수치 전체의 정확성, 인용의 의미상 뒷받침, AI 답변 정확도, 예측 성능을 입증하지 않는다. 보고서는 서명된 진위 증명도 아니다. 원문 준비와 Chroma 색인은 별도이며, 준비 버튼은 벡터 색인을 생성하지 않는다. 새 회사의 Chroma 자료가 없을 때 임베딩 모델을 불필요하게 로드하지 않는다.

공식 IR 목록의 구조와 주소는 바뀔 수 있다. 현대차·Apple에는 실제 확인한 개별 실적 발표 주소도 등록돼 있다. 다음 분기의 링크를 자동 발견하지 못하면 프로필을 갱신해야 한다. 오래된 자료는 기간 조건에서 탈락하며, 날짜/기간을 추측해 채택하지 않는다. 외부 제공자의 접근 제한은 준비 완료로 우회하지 않는다.

## Windows에서 사용

기업을 검색하고 후보를 고른 뒤 **기업 근거 준비·충족도 확인**을 실행한다. 국내 공시에는 본인 DART 키, 미국 공시에는 프로젝트명과 연락 가능한 이메일을 포함한 SEC User-Agent가 필요하다. 해당 연락처는 SEC 요청 헤더로 전달된다. 이 단계는 모델과 Docker를 실행하지 않으며 유료 AI 호출이 없다. 실제 분석에는 기존 OpenAI·Docker·SearXNG 설정이 필요하다.

공식 자동 게시 설정의 **준비된 6개 기업** 모드는 근거가 충족된 기업 중 최근 새 공시/실적 발표를 우선하고, 새 사건이 없으면 관심도 점수가 가장 높은 기업을 고른다. 관심도는 전 거래일 주가 변동을 그 기업의 최근 변동성으로 나눈 값과, 최근 2일 뉴스량을 같은 주 앞선 5일의 하루 평균으로 나눈 값을 각각 4에서 자른 뒤 평균한 것이다(`tools/attention_signal.py`). 최근 2일 안에 공식 게시한 기업은 다른 후보가 있으면 제외한다. 주가·뉴스 신호를 모두 구하지 못하면 가장 오래 공식 게시하지 않은 기업을 고른다. 뉴스량은 선정 시점에 로컬 SearXNG가 이미 실행 중일 때만 조회하며, 2026-11-11 실측에서는 날짜가 있는 기사가 기준(5건)에 못 미쳐 주가 변동만으로 점수가 계산됐다. 이 신호는 기업 선정에만 쓰고 토론 근거로 쓰지 않으며, 선정 사유(`new_official_event`·`attention`·`rotation`)는 준비 보고서에, 신호 값은 PC의 실행 상태에만 남긴다. 시장 전체의 인기·거래량 순위를 뜻하지 않는다. 기존 저장 설정은 삼성전자 고정을 유지한다. 모드를 바꾸려면 새 프로그램에서 설정을 직접 저장해야 하며 이때 당일 실행을 시작할 수 있다.

같은 날 재시도는 기업과 원문 묶음을 고정한다. 본문이 바뀌면 이전 분석 체크포인트를 섞어 쓰지 않는다. 기존 체크포인트 파일은 보존하고, 기업·티커·날짜·모델·코드/빌드·본문 해시를 포함한 별도 경로를 사용한다. 게시만 실패한 경우 저장한 결과를 다시 사용한다. 하루 공식 게시 및 최대 분석 시도 제한은 유지한다.

## CLI와 관리자 보고서

소스 실행은 `.env`의 DART/SEC 설정을 사용할 수 있다. 아래 명령은 공개 원문 수집과 검사를 수행하고, AI 분석·업로드·공식 게시를 하지 않는다.

```powershell
venv\Scripts\python.exe -m app.prepare_company_evidence --refresh --output evidence-readiness.json
```

`--refresh`를 생략하면 디스크에 저장된 원문과 이전 수집 실패 상태만 재검사한다. `--company`와 `--ticker`를 함께 주면 한 기업만 점검한다. `--base-dir`로 별도 캐시를 지정할 수 있다. 기본 Windows 캐시는 실행 프로세스의 `%LOCALAPPDATA%\MarketCouncil\company-evidence`다. 패키지/샌드박스 프로필은 일반 Windows 프로필과 경로가 다를 수 있다.

관리자 화면의 **기업별 근거** 탭은 6기업 전체 보고서 JSON을 가져와 기존 관리자 전용 저장소에 보관한다. 한 기업 진단 파일은 관리자 일괄 보고서가 아니다. `.inventory.json`은 소스 등록부/파일 존재 현황이며 벡터 검색 품질 측정이 아니다. 원문·토큰·키·로컬 경로는 관리자 보고서에 넣지 않는다.

결과에 새 보고서가 있으면 비공개 업로드에서도 회사·티커·문서·해시 일치를 검사한다. 기존 보고서 없는 결과는 계속 읽고 개인 저장할 수 있다. 새 공식 지정 경로는 오늘의 준비 완료 보고서를 요구한다. 이 클라이언트 운영 검사는 기존 Supabase 소유권/RLS와 다른 역할이며, 운영자 권한을 가진 사람이 DB 함수를 직접 호출하는 것을 막는 서버 측 진위 증명은 아니다. 이번 작업은 DB 권한과 과거 공개 결과를 변경하지 않는다.

## 검증 범위

합성 오류/변조·교차 기업·최신 자료 실패·체크포인트·업로드 회귀 검사와 실제 공개 원문 수집을 분리한다. 실제 수집 성공을 유료 전체 토론이나 RAG 의미 품질 통과로 표시하지 않는다. 기업별 의미 평가에는 사람 정답, 수치·기간 검수와 독립 사례 비교가 추가로 필요하다.


## 미국 발행사 원문 대체 경로

SEC 요청이 제한되면 Apple 공식 IR 공개 공시 피드 또는 Microsoft 공식 SEC Filings 페이지가 연결한 원본 PDF/Word 공시를 사용한다. 공식 발행사 링크에서만 파일 주소를 발견하고 HTTPS 호스트/경로·리다이렉트·공개 IP·용량·원문 종류·법인명/세금 식별자·Form 10-K/10-Q·보고 기간을 검사한다. SEC 접근 제한을 우회하거나 제3자 미러의 재작성 본문을 공시로 취급하지 않는다.

Apple은 발행사 피드의 제출일을 사용한다. 정확한 공개일을 제공하지 않는 Microsoft 파일은 해당 원문 버전을 처음 확보한 날짜를 date_basis=first_retrieved로 기록하고 관리자에서 최초 공개 확인일로 표시한다. 이는 실제 제출일과 다르며 과거 기준일로 소급하지 않는다. 원문 해시가 바뀐 새 버전도 처음 관측한 날짜를 기록한다. 최신 필수 공시 원문을 확보하지 못하면 과거 캐시로 대체하지 않는다.
