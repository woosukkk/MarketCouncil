## RAG·인용·답변 품질

- 3개 쟁점, 2라운드, 최종 요약을 저장했다. 최종 쟁점 상태는 **자료 부족(`UNKNOWN`) 2개 / 미해결(`OPEN`) 1개**이며 추가 확인 근거 6개가 남았다.
- 원본 카탈로그의 자료·인용 쌍을 다시 구성해 남은 인용 32회, 고유 인용 10개를 대조했다. ID 불일치·문구 불일치·인용 연결 오류·인용이 없는 발언 쟁점은 각각 0개였다.
- 인용에서 수치를 확인하기 어려운 검토 신호 **4개**, 오래된 전망 인용 경고 **1개**가 있었다. 근거 보완 문구와 자료 부족 상태는 실제 웹에서도 확인했다.
- 서울경제의 삼성바이오로직스 노사 기사가 `source_type=official`로 저장돼 ‘공식 자료’로 표시됐다. 출처 분류 오류와 삼성전자 직접 근거로 사용할 적합성 검토가 남아 있다.
- 확인한 분류 원인: 해당 원문은 분류된 기사·근거 목록에서 빠져 유형이 빈 값이었다. `app/debate_workflow.py`가 이 문서도 카탈로그에 전달했고, `tools/evidence_catalog.py`의 `_web_source_type`이 빈 유형을 검색 의도 `search_focus=official`로 대체했다. 공식 도메인 검사 결과가 이 경로에는 반영되지 않았다. 검색 의도를 출처 신뢰도로 승격한 것이 직접 원인이며, 해당 문서가 분류 목록에서 빠진 이유는 미확정이다. 이번에는 코드나 이미 게시한 결과를 수정하지 않았다.
- 인용 연결 성공은 주장 자체의 진실성·인과관계·투자 판단의 정답을 입증하지 않는다. 발언의 의미 검증 상태도 `not_evaluated`다. 정답 자료가 있는 Recall·MRR·nDCG 벤치마크나 독립 전문가 평가를 이번 실행에서 수행하지 않았다.

## 운영·관측 시 주의점과 다음 개선

1. **출처 분류·기업 적합성:** 언론 기사와 기업 공식 문서를 구분하고, 계열사 자료를 대상 기업의 직접 근거로 사용할 때 별도 확인이 필요하다.
2. **수치·전망 근거:** 경고가 남은 발언은 최신 직접 인용·계산 근거를 보완해야 한다. 추가 LLM 재분석으로 경고를 숨기지 않았다.
3. **비용·지연 측정:** 초기 분석 등 전체 호출의 사용량과 단계별 대기 시간을 계측해야 한다. 현재 구조화 입력만 약 74.6만 토큰이므로 반복 입력도 후속 최적화 대상이다.
4. **화면 갱신:** 기존 운영 웹은 최초 로딩 시 목록을 읽는다. 새 게시를 보려면 새로고침이 필요하다. 이번에는 실제 새로고침 후 노출을 검증했다.
5. **관측 경로:** Codex의 상태 파일 읽기는 MSIX 가상화 때문에 과거 `LocalCache` 사본으로 연결됐다. 10월 20일 체크포인트는 실제 AppData 경로로 연결됐다. 오래된 상태 파일만으로 실행 실패를 판단하지 않았으며, 실제 예약 작업·해당 실행 ID·서버 상태·브라우저 화면을 교차 검증했다. 기존 가상화 사본은 삭제하지 않았다.

애플리케이션 코드·프런트엔드·설치 실행 파일·운영 DB 스키마를 이번 검증에서 변경하거나 재배포하지 않았다. 새 분석 데이터만 공식 게시했다. 검증 시점의 다음 예약은 **2026-10-21 09:00 KST**였으며 PC 로그인·인터넷·Docker·API 사용 준비가 필요하다.
