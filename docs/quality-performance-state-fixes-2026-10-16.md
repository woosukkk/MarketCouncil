# 품질·실행 성능·저장 공개 상태 수정 검증

검증일: 2026-10-16 (한국 시간). 운영 웹 배포와 Supabase DB는 변경하지 않았다.

## 1. 근거 품질

### 원인과 수정

- 웹 마크다운 앞 1,200자를 먼저 잘라 기사 본문 대신 메뉴·로고가 입력됐다. 이제 기사 영역의 본문·표를 정제한 뒤 길이를 제한한다. 본문이 없으면 검색 요약임을 명시하고, 제목·메뉴뿐이면 근거에서 제외한다.
- 인용 후보를 줄마다 잘라 15자 미만 숫자와 표의 짧은 행이 빠졌다. 인접한 표 항목과 수치를 원문의 연속 구간으로 묶고, 중복과 페이지 탐색 문구를 제거한다.
- 재무 원 단위 수치를 모델이 임의 환산하지 않도록 KRW→조원 값을 Decimal로 계산해 함께 제공한다.
- 출처·인용 ID, 수치, 미래 자료 검사에서 핵심 문제가 발견된 쟁점은 중재자가 해결됨으로 승격하지 못하게 UNKNOWN으로 제한한다. 원래 모델 판정과 검토 사유는 보존한다.

### 같은 저장 입력 검사

문제가 있었던 웹 캐시 두 건을 외부 요청 없이 재추출했다. 원래는 각 16개 후보가 모두 링크였고, 수정 후 각 3개 본문 인용에 메뉴 인용은 0개였다. 별도 공시 구간에서는 기존 후보에 없던 취득 수량이 원문과 일치하는 인용에 포함되는 것을 확인했다. 이는 해당 입력 회귀검사이며 전체 답변 정확도나 할루시네이션 감소율이 아니다.

## 2. 전체 실행 성능

### 수정

- 같은 자료를 읽는 최초 Bull/Bear 분석을 두 작업으로 병렬 실행한다.
- 독립 작업이 함께 완료돼도 완료 기록이 유실되지 않도록 체크포인트 쓰기를 잠근다. 실패한 작업만 재개할 수 있다.
- 검색 수집이 끝나면 BGE 모델 참조를 해제해 이후 AI 응답 대기 동안 보유하지 않는다. 모델을 다시 쓰는 다음 분석에서는 다시 로드한다.
- 토론의 공통 입력을 앞에 고정하고 변화하는 라운드 상태를 뒤에 둔다. 실제 제공 카탈로그의 출처 ID·인용 ID·원문이 모두 일치하는 중복 인용문만 요청에서 생략한다. 저장 결과와 근거는 보존한다.
- 초기 분석·프롬프트 등 실행 의존성이 바뀌면 이전 체크포인트를 섞지 않도록 서명 범위를 보완했다.

### 통제된 입력 비교

저장된 같은 토론 6회 요청을 오프라인 재생했다. 출처 159개·인용 791개를 유지한 상태에서 입력 텍스트는 538,781→479,808토큰으로 58,973토큰(10.946%) 감소했다. 이 비교는 직렬화 변경만의 토큰 차이며 실제 청구량·실행 시간 비교가 아니다.

### 실제 삼성전자 분석 1회

| 항목 | 측정 |
|---|---:|
| 종료 상태 | 성공, 2라운드 |
| 전체 경과 시간 | 380.622초 (6분 21초) |
| CPU 사용 시간 | 47.375초 |
| API 호출 | 15회, 전부 완료 |

| 추정 Standard 토큰 비용 | 약 US$0.212 |

최초 Bull/Bear 호출은 실제로 겹쳐 실행됐고 각각 약 31.1초·32.6초였다. 둘째 라운드 Bull/Bear/중재자 요청에서 캐시 입력 239,872토큰이 관측됐다. 계정 전체 캐시의 기여와 이번 변경의 기여를 완전히 분리한 실험은 아니다.

직전 실행의 중단·재개를 합친 실제 활동 시간은 601.902초였다. 이번에는 입력·출력·기사·캐시 상태가 다르므로 두 수치의 차이를 성능 개선율로 제시하지 않는다. 최대 메모리는 여전히 약 2GiB가 필요하며 모델 해제는 지속 점유를 줄이는 조치다. 시작 시 시스템 가용 메모리는 약 765MiB였고 실행 중 메모리 압박이 관측됐다.

비용은 관측 토큰에 [OpenAI 공식 GPT-5 mini 요금](https://developers.openai.com/api/docs/models/gpt-5-mini)을 적용한 추정치다. 계정 청구서·세금·호스팅 비용을 확인한 값은 아니다. 원문·API 키·로그는 GitHub 기록에 포함하지 않았다.

### 수치 표기 후속 검증

실제 생성된 발언에는 수치 검토 경고 7건이 있었다. 복합 원화 표기(조·억)와 표의 명시적 원·주 단위를 인식하도록 보완한 뒤, 같은 저장 결과에 검사기만 다시 적용했다. 경고는 5건으로 줄었다. 원문·발언·중재자 판정은 바꾸지 않았고 추가 API 호출도 하지 않았다. 남은 불일치를 없애려고 허용폭을 늘리지는 않았다. 기존 표시 정밀도에 따른 반올림 규칙을 유지하며, 허용폭 밖의 값은 계속 검토 대상으로 남긴다.

전체 실행은 후속 표기 보완 전의 소스 사본에서 측정했다. 최종 표기 검사와 DB 사전 검사는 별도 단위·통합 검사로 검증했다. 최종 소스를 다시 유료 전체 실행한 수치는 아니다.

## 3. 저장·공개 상태

- 비공개·링크 공유 전환 시 공식 지정 참조만 해제하고 분석 본문은 보존한다.
- 공식 목록 RLS는 연결된 공개 토론만 허용하며, 기존에 남은 비공개 참조는 메타데이터만 정리한다.
- 공식 지정은 한국 날짜를 확인하고 동시 요청을 순서대로 처리한다. 같은 결과 재시도는 허용하고 자동 게시가 다른 공식 결과를 덮어쓰지 못하게 한다. 운영자의 명시적 수동 교체는 가능하다.
- 기존 잘못된 payload도 비공개 회수는 가능하다. 신규 저장·payload 수정·재공개·공유 링크 재발행은 형식을 검증한다.
- 업로드·공개 변경·삭제·공식 지정 후 목록을 갱신하며 창으로 돌아오면 외부 PC 업로드도 다시 조회한다. 같은 토론을 여러 날 지정했을 때 최신 공식일을 유지한다.
- 웹·PC 업로드는 분석 기준일 analysis_as_of를 보존한다.
- 운영 DB가 구버전이면 유료 분석 전에 새 RPC 지원 검사를 수행해 중단하고, 필요한 마이그레이션을 안내한다. NULL 토론을 이용한 사전 검사는 게시 상태를 바꾸지 않는다.

### 운영 적용 순서

1. supabase/discussion-result-validation.sql
2. supabase/discussion-publication-state.sql
3. 웹 배포와 데스크톱 배포 프로그램 갱신

현재는 소스 수정·로컬 검증 단계다. **운영 DB 적용 전에는 새 로컬 자동 공식 분석이 의도적으로 중단될 수 있다.** 기존 웹은 유지하며 운영 DB·웹·배포 프로그램의 실제 연동 검증은 배포 단계에서 수행해야 한다.

## 4. 검증 범위와 남은 한계

- 별도 커밋 소스 사본에서 Python 회귀 175개 및 함수형 검사 7개 통과.
- 웹 단위 테스트 37개, 프로덕션 빌드 통과.
- PostgreSQL 통합 테스트 10개 통과: 권한·철회·동시 지정·날짜·명시 교체·삭제·기존 CHECK 오류 재현·마이그레이션 반복 적용·NULL 사전 검사. 공통 JSON 계약 19개 사례의 SQL 결과도 대조했다.
- 실제 AI 발언 12개의 의미 지원 여부는 전문가 정답셋으로 평가하지 않았다. 숫자 일치나 원문 연결은 투자 주장의 사실성 보증이 아니다.
- 재업로드 경로별 중복 결과 ID 통합, 사용자별 저장 총량 제한, 북마크 기능 문제는 이번 범위에서 해결하지 않았다.
- 원래부터 있던 사용자 작업 파일과 보고서는 보존했다. 실제 분석 결과는 로컬에만 저장했고 공식 게시하지 않았다.
