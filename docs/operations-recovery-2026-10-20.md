# MarketCouncil 운영 복구 결과 — 2026-10-20

## 결론

자동 공식 게시를 분석 시작 전에 차단하던 운영 DB 함수 불일치를 해결했다. 실제 운영자 계정의 인증 갱신과 게시 준비 검사가 통과했으며, 기존 토론 6개와 공식 지정 6개는 모두 유지됐다. 새 분석·업로드·공식 게시는 실행하지 않았다. 현재 최신 공식 토론은 10월 16일이며, 10월 20일 결과를 새로 게시한 것은 아니다.

## 확인한 원인

- 10월 17·19·20일의 `OfficialSchemaRequired` 4건: 로컬 프로그램은 새 공식 게시 함수를 요구했지만 운영 DB에는 이전 함수만 있었다. 준비된 DB 변경이 적용되지 않아 사전 검사에서 중단됐다. AI 분석이나 OpenAI 잔액 오류가 아니다.
- 10월 18일 계정 연결 실패 1건: 기존 로그로는 DNS·연결·시간 초과 중 세부 원인을 확정할 수 없다. 인증 키가 잘못됐다는 증거도 없다. 세부 진단 보존과 안전한 읽기 재시도를 추가했다.
- 오전 9시에 PC가 절전·종료된 날이 있었다. 10월 20일은 절전 복귀 후 Windows의 보충 실행이 작동했지만, 위 DB 준비 검사에서 실패했다.

## 적용 내용

### 운영 DB

`supabase/discussion-result-validation.sql` 다음 `supabase/discussion-publication-state.sql`을 하나의 트랜잭션으로 적용했다.

- 결과 형식 검증과 공개 상태 전환 검증을 추가했다. 비공개 전환 시 토론 본문을 보존하고 공식 지정 참조만 제거한다.
- 공식 지정 함수에 운영자·소유자·결과 형식·한국 날짜 검사를 적용했다. 같은 결과의 재시도는 허용하며 다른 결과로 같은 날짜를 덮어쓰려면 명시적인 교체 요청이 필요하다.
- 날짜별 잠금과 자정 경계 검사를 적용해 동시 지정과 날짜 변경 충돌을 방어한다.
- 익명 사용자의 운영자 검사·공식 지정 함수 직접 실행 권한을 제거했다. 기존에는 기본 실행 권한이 있었지만 함수 내부 운영자 검사가 존재했으므로, 익명 게시나 정보 유출이 발생했다고 판단할 근거는 없다.
- 최초 편집기 입력 시도는 텍스트 치환 문제로 구문 분석 단계에서 실패했다. 전체 SQL 일치 검증과 재실행 승인을 거친 다음 적용에 성공했다. 상세 배포 이력은 GitHub #21에 기록한다.

### 로컬 통신 처리

- `desktop/cloud.py`: 일시적인 통신 오류에 대해 GET·HEAD 읽기 요청만 최대 3회 시도한다. 인증 갱신·업로드·게시 등 POST 요청은 중복 실행을 방지하기 위해 자동 반복하지 않는다. HTTP 오류·인증서 오류·영구적인 DNS 오류도 반복하지 않는다.
- `desktop/daily_official.py`: 실패 기록에 오류 분류·시도 수·허용된 운영체제 오류 코드만 남긴다. URL·인증 정보·응답 본문은 진단 정보에 포함하지 않는다.
- `test_cloud_network.py`, `tests/test_publication_sql.py`: 통신 재시도와 DB 권한·게시 상태 회귀 검사를 추가했다.
