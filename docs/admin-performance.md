# 관리자 성능 기록

운영자 로그인 후 `/app?view=admin`에서 운영 모니터링과 RAG 벤치마크를 확인합니다. Supabase `admin_reports`는 공식 운영자만 읽고 본인 명의로 추가할 수 있습니다. 일반 사용자와 비로그인은 차단됩니다. 수정·삭제는 허용하지 않습니다. 최근 200건을 표시합니다.

## 로컬 분석 시간
소스의 desktop/main.py로 실행하는 다음 분석부터 로컬 데이터 폴더의 metrics에 JSON을 저장합니다. 성공·실패, 전체 실행 시간과 CPU 시간을 기록하고 원문·프롬프트·오류 내용·키는 저장하지 않습니다. 기존 desktop 0.4.0 패키지에는 이 수집기가 없습니다. 관리자 화면에서 JSON을 가져오면 비밀 필드를 제외한 허용 항목만 업로드합니다. 자동 원격 전송은 하지 않습니다.

업로드 표본만 집계하므로 전체 서비스 가용성이 아닙니다. 토큰·비용·단계별 시간은 미측정입니다. Lighthouse 기록은 모바일 실험실 측정이며 실제 사용자 평균과 구분합니다.

## 정답 기반 RAG 검색 평가
`benchmarks/rag.dataset.template.json`을 로컬에 복사하고 cases에 실제 문서를 검토한 정답을 작성합니다. 빈 템플릿은 실행을 거부합니다. 각 사례에는 id, query, company, as_of_date(YYYY-MM-DD), expected 목록이 필요합니다. expected의 각 항목은 실제 검색 결과의 source와 선택적인 chunk_id를 사용합니다. source만 지정하면 해당 문서의 모든 청크가 정답 후보입니다. source와 chunk_id를 지정하면 해당 청크만 정답입니다. 임의로 만든 정답은 점수 근거가 되지 않습니다.

실행: `python -m tools.rag_benchmark LOCAL_GOLD.json --top-k 5 --repeats 3 --output results/metrics/rag.json`

LLM 호출 없이 현재 ReportRetriever를 평가합니다. 모델 준비를 위한 첫 검색은 시간 집계에서 제외합니다. 문서 저장소가 비어 있거나 평가 중 바뀌면 저장하지 않습니다. 데이터셋·문서 저장소 해시, 모델명, 검색 개수, 반복 수를 함께 보관합니다. 같은 조건끼리 비교하세요. 모델 준비·문서 수집 시간은 검색 지연에 포함되지 않습니다.

Recall은 지정한 정답 근거 중 검색된 비율, precision은 반환 결과 중 정답 비율, MRR은 첫 정답 순위의 역수입니다. 사례와 반복의 평균을 표시합니다. p95는 관측 검색 시간의 nearest-rank 방식입니다. 기업 혼입·기업 미상·기준일 이후 자료 수는 모든 반복을 합산합니다. 보고서에는 질문·원문 대신 사례 ID와 수치만 담습니다. 정답 데이터셋은 공개 저장소에 커밋하지 마세요.

아직 실제 정답 데이터셋을 구성·실행하지 않았으므로 실제 RAG 점수는 없습니다. 답변 사실성·인용 정확도·LLM 평가와 예측 수익률은 이번 검색 벤치마크 범위에 포함하지 않습니다.
