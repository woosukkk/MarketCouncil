# 관리자 성능 기록

운영자 로그인 후 `/app?view=admin`에서 운영 모니터링과 RAG 벤치마크를 확인합니다. Supabase `admin_reports`는 공식 운영자만 읽고 본인 명의로 추가할 수 있습니다. 일반 사용자와 비로그인은 차단됩니다. 수정·삭제는 허용하지 않습니다. 최근 200건을 표시합니다.

## 로컬 분석 시간
Windows 프로그램 0.5.0 이상 또는 소스의 desktop/main.py로 실행하는 다음 분석부터 로컬 데이터 폴더의 metrics에 JSON을 저장합니다. 성공·실패, 전체 실행 시간과 CPU 시간을 기록하고 원문·프롬프트·오류 내용·키는 저장하지 않습니다. 기존 desktop 0.4.0 패키지에는 이 수집기가 없습니다. 관리자 화면에서 JSON을 가져오면 비밀 필드를 제외한 허용 항목만 업로드합니다. 자동 원격 전송은 하지 않습니다.

업로드 표본만 집계하므로 전체 서비스 가용성이 아닙니다. 기존 Windows 0.5.0 기본 수집기는 토큰·비용·단계별 시간을 측정하지 않습니다. 최신 소스는 아래 상세 계측을 지원하며 과거 기록을 소급 생성하지 않습니다. 2026-10-15 별도 실제 분석 검증에서는 전체 API 사용량·구간 시간·메모리를 계측했으며, [실행·품질 검증 보고서](live-analysis-verification-2026-10-15.md)에서 범위와 한계를 확인할 수 있습니다. Lighthouse 기록은 모바일 실험실 측정이며 실제 사용자 평균과 구분합니다.

## 정답 기반 RAG 검색 평가
`benchmarks/rag.dataset.template.json`을 로컬에 복사하고 cases에 실제 문서를 검토한 정답을 작성합니다. 빈 템플릿은 실행을 거부합니다. 각 사례에는 id, query, company, as_of_date(YYYY-MM-DD), expected 목록이 필요합니다. expected의 각 항목은 실제 검색 결과의 source와 선택적인 chunk_id를 사용합니다. source만 지정하면 해당 문서의 모든 청크가 정답 후보입니다. source와 chunk_id를 지정하면 해당 청크만 정답입니다. 임의로 만든 정답은 점수 근거가 되지 않습니다.

실행: `python -m tools.rag_benchmark LOCAL_GOLD.json --top-k 5 --repeats 3 --output results/metrics/rag.json`

LLM 호출 없이 현재 ReportRetriever를 평가합니다. 모델 준비를 위한 첫 검색은 시간 집계에서 제외합니다. 문서 저장소가 비어 있거나 평가 중 바뀌면 저장하지 않습니다. 데이터셋·문서 저장소 해시, 모델명, 검색 개수, 반복 수를 함께 보관합니다. 같은 조건끼리 비교하세요. 모델 준비·문서 수집 시간은 검색 지연에 포함되지 않습니다.

Recall은 지정한 정답 근거 중 검색된 비율, precision은 반환 결과 중 정답 비율, MRR은 첫 정답 순위의 역수입니다. 사례와 반복의 평균을 표시합니다. p95는 관측 검색 시간의 nearest-rank 방식입니다. 기업 혼입·기업 미상·기준일 이후 자료 수는 모든 반복을 합산합니다. 보고서에는 질문·원문 대신 사례 ID와 수치만 담습니다. 정답 데이터셋은 공개 저장소에 커밋하지 마세요.

2026-10-15에는 로컬 문서를 대조한 12문항 파일럿을 실행했습니다. 실제 수치와 편중·라벨 한계는 [수정·검색 검증 보고서](verification-2026-10-15.md)에 기록했습니다. 독립 전문가 정답 세트나 전체 서비스 정확도는 아닙니다. 답변 사실성·인용 정확도·LLM 평가와 예측 수익률은 이번 검색 벤치마크 범위에 포함하지 않습니다.


## 상세 계측: 최신 소스 실행

`measure_analysis`의 같은 실행 안에서 자료 수집·검색·최초 관점 분석·토론·최종 요약·후속 쟁점 단계를 기록합니다. Bull/Bear 병렬 스레드와 LangGraph 노드에도 실행 문맥을 전달합니다. 완료 단계를 재사용하면 `cached` 기록만 남기며 과거 API 사용량을 새 실행에 다시 합산하지 않습니다.

분석 시간에는 워크플로 초기화와 분석 본체가 포함됩니다. Docker·브라우저 준비, 결과 저장·업로드·공식 지정은 이 시간의 범위 밖입니다. 단계는 상위·하위 또는 병렬 실행이 겹치므로 단계 시간이나 API 요청 시간을 합쳐 전체 시간이라고 표시하면 안 됩니다. 단계는 최대 1,000개이며 초과 여부를 별도로 기록합니다.

모든 프로젝트 Responses 호출은 공통 계측을 통과합니다. 요청·오류 횟수, 관측 입력·출력·캐시 입력·추론 토큰, API 단계별 요청 시간과 관측 토큰 비용을 보고합니다. 명시적 재시도는 각 호출로 집계하지만 SDK 내부 재시도의 횟수·사용량은 알 수 없습니다. API 오류율과 분석 실행 실패율은 다른 지표입니다.

입력과 캐시 입력, 출력과 추론 토큰을 이중 합산하지 않습니다. 사용량이 없는 실패·응답은 미측정이며 0원으로 처리하지 않습니다. 일부 호출만 알면 토큰·비용의 부분 관측임을 표시합니다. 웹 검색 등의 별도 도구 요금, 세금, 계정 청구서는 포함하지 않습니다.

단가는 `benchmarks/openai-pricing-2026-10-27.json`의 날짜별 Standard USD 스냅샷을 기본 사용합니다. [GPT-5 mini 공식 단가](https://developers.openai.com/api/docs/models/gpt-5-mini)를 확인했으며 백만 토큰당 입력 0.25·캐시 입력 0.025·출력 2.00달러입니다. 최신 요금을 자동으로 조회하지 않습니다. `RESULTS_PRICING_FILE`로 별도 스냅샷을 지정할 수 있으며, 잘못된 파일·모델 불일치·누락 정보·지원하지 않는 요금 조건에는 정가를 임의 적용하지 않습니다.

새 상세 필드는 Windows 0.6.0 이상 또는 현재 소스의 다음 실행부터 생성됩니다. 기존 0.5.0에는 상세 수집이 없으므로 새 ZIP을 별도 폴더에 풀어 실행하세요. 자동 게시를 이용한다면 설정을 다시 저장해 예약 경로를 갱신하세요. 관리자 화면은 예전 전체 시간 보고서도 계속 읽습니다.

## 답변 근거 품질: 로컬 검토와 별도 예측 비교

RAG 검색 결과와 답변 주장의 의미 품질은 다른 평가입니다. 새 `답변 근거 품질` 탭은 기존 `rag` 저장 종류의 `answer_quality` 범위를 사용하며 검색 평가와 섞지 않습니다. 운영 DB·RLS 변경은 필요하지 않습니다.

1. `python -m tools.quality_benchmark export LOCAL_RESULT.json --output LOCAL_REVIEW_QUEUE.json`
2. 로컬 큐의 주장·선택 인용을 확인하고 각 사례의 `review.origin`을 `human`, `review.label`을 아래 고정 라벨로 검수합니다. 자동 생성된 큐는 모두 `unreviewed`입니다.
3. 별도 예측 파일에 같은 `case_id`·`input_hash`와 판정 라벨을 넣습니다. 입력 해시가 다르거나 사례가 중복되면 비교를 거부합니다. 모델 판정은 사람 정답으로 승격하지 않습니다.
4. `python -m tools.quality_benchmark evaluate LOCAL_REVIEW_QUEUE.json --predictions LOCAL_PREDICTIONS.json --output SAFE_REPORT.json`
5. 관리자 화면에서 `SAFE_REPORT.json`만 가져옵니다. 예측 파일은 생략할 수 있으며 사람 정답이나 비교 예측이 없으면 의미 판정은 미평가입니다. 기존 파일은 자동으로 덮어쓰지 않습니다.

검수 라벨:

- `supported`: 주어진 인용이 핵심 검증 가능 주장을 뒷받침합니다. 기업·지표·기간·통화·증감 방향도 맞는지 확인합니다.
- `contradicted`: 주어진 인용이 핵심 주장과 직접 모순됩니다.
- `insufficient_evidence`: 인용만으로 핵심 주장을 확인할 수 없거나 추가 문맥·자료가 필요합니다.

규칙 검사는 인용 ID·수치·기준일을 별도로 점검합니다. 숫자가 있다는 이유로 기간·방향·인과 추론까지 맞는 것으로 처리하지 않습니다. 집계는 저장된 최종 인용을 다시 검사한 결과이므로 생성 중 제거된 모든 잘못된 인용 시도의 횟수와 동일하지 않습니다.

`semantic_accuracy`는 제공된 사람 정답과 별도 예측의 판정 일치율입니다. 투자 사실성·수익률·전체 서비스 정확도를 뜻하지 않습니다. 사람 출처는 입력자의 선언이며 독립 전문가 검수의 진위를 인증하지 않습니다. 실제 사례와 합성 회귀 사례를 구분하며 정답 검수 범위와 비교 사례 수를 함께 표시합니다.

원문·발언·출처 URL은 로컬 검토 큐에만 둡니다. 관리자용 보고에는 고정 ID·라벨·해시·규칙 플래그·수치만 포함합니다. 사례와 집계·출처·혼동행렬 정합성을 검사하지만 해시는 원본 진위에 대한 전자서명이 아닙니다. 검토 큐를 공개 저장소나 결과 공개 버킷에 올리지 마세요.
