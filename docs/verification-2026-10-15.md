# MarketCouncil 오류 수정·성능·품질 검증

점검일: 2026-10-15

## 결론

기업 검색·결과 형식·출처 귀속·적자 구간 계산·공개 파일 선택·과거 시점 검색을 소스에서 수정했다. 사용자 경험 개선은 보류했고 Vercel 재배포, Windows 패키지 재배포, 운영 DB 변경은 실행하지 않았다.

실제 로컬 문서 검색의 초기 평가에서는 지정 정답을 상위 5개에서 찾은 비율이 **50% → 75%**로 개선됐다. 오늘 생성된 결과의 인용 원문 연결도 검사했지만, 생성 답변의 사실성과 주장–인용 적합성까지 검증 완료된 것은 아니다.

### 적용 범위 주의

- 변경은 소스에 반영했다. 배포된 웹과 다운로드용 desktop 0.4.0에는 아직 적용되지 않는다.
- 로컬 자동 작업은 이 작업 폴더의 소스를 실행하므로 다음 실행부터 변경의 영향을 받을 수 있다. 이 검증에서 자동 작업이나 유료 분석을 새로 시작하지 않았다.
- DB 신규 설치 SQL과 기존 DB용 형식 제약 마이그레이션을 준비했지만 운영 DB에는 적용하지 않았다. 실제 PostgreSQL 실행 검증도 남아 있다.
- 공식 출처 판정은 확인된 SEC/DART 호스트를 우선한다. 등록하지 않은 기업 IR 자료는 보수적으로 미분류가 될 수 있다.
- 명시적 공개 파일 목록을 만들지 않았으므로 옛 전체 공개 명령은 안전하게 중단된다. 기존 공개 파일을 삭제하거나 비공개로 바꾸지는 않았다.

## 2. 회귀 검증

- Python 통합 검사 **78개 통과**. 기업 검색, 재무 전환, 실제 메모리 Chroma의 기준일 필터, 자동 실행·단계 복구·토론 종료·성능 기록·업로드·공식 권한·국면 계산을 포함한다.
- 출처 분류 검사는 실제 API 대신 가짜 응답으로 미수집 URL·없는 ID·변조 메타데이터·유사 공식 도메인·분류 실패를 검증했다.
- 웹 단위 검사 **33개 통과**, 로컬 빌드 성공. 기존 공개 결과 13개 모두 새 열람 검사 통과. 오늘의 실제 분석은 Python 업로드 형식 검사 통과.
- 가짜 Supabase 주소·키와 차단한 외부 요청으로 로컬 브라우저 5개 시나리오를 검증했다: 정상 상세의 4개 탭, 잘못된 의제, 잘못된 요약, 예기치 않은 렌더링 오류 격리, 옛 텍스트 결과 열람. 목록의 잘못된 의제 항목도 함께 확인했다.
- 운영 계정 로그인·새 게시·공개 권한 변경·운영 DB 변경을 테스트로 수행하지 않았다.

## 3. 실제 RAG 성능·검색 품질

### 측정 방법

실제 로컬 Chroma 색인 4,087개 청크와 기존 BGE-M3를 사용했다. 삼성전자 문서 6개의 첫 페이지 청크를 읽고 질문 12개와 정답 source/chunk ID를 작성한 뒤, 동일한 자료로 수정 전·후 검색을 각각 3회씩 측정했다. 각 버전은 36번 검색했다.

정답은 검색 결과를 보고 역으로 선택하지 않았다. 다만 개발 점검 과정에서 원문을 대조해 작성한 작은 평가이며 독립 전문가가 감수한 데이터셋은 아니다. 질문에 보고서 날짜·기관명·수치가 포함된 문서 찾기 성격이 강하고, 회사 한 곳·첫 페이지에 편중돼 있다.

| 지표 | 수정 전 | 수정 후 |
|---|---:|---:|
| Recall@5 / 지정 정답 적중률 | 50.0% (6/12) | **75.0% (9/12)** |
| MRR / 첫 정답 순위 점수 | 0.389 | **0.447** |
| 검색 시간 중앙값 | 412.1ms | **325.2ms** |
| 검색 시간 p95 | 468.3ms | **443.4ms** |
| 다른 기업·기업 미상 결과 | 0 | 0 |
| 기준일 이후 결과 | 0 | 0 |

Recall@5는 지정한 정답이 검색 결과 5개 안에 있는지, MRR은 첫 정답이 위에 나오는지를 나타낸다. p95는 측정의 95%가 해당 시간 안에 끝난다는 뜻이다.

### 해석의 한계

- 반복은 12개 질문의 각 3회다. 독립적인 36개 질문을 평가한 것은 아니다.
- 정답 청크를 문서마다 하나만 지정했다. 라벨을 붙이지 않은 다른 관련 청크도 있을 수 있으므로 기록 파일의 엄격한 Precision 값을 실제 무관 자료 비율로 해석하지 않는다.
- 모델 준비·첫 검색은 위 시간에서 제외했다. 별도 프로세스의 모델 준비와 첫 검색은 약 30.8초였다. 프로그램 전체 시작 시간과 같지는 않다.
- 버전별 검색을 순서대로 측정했으므로 캐시·PC 상태의 영향이 남는다. 위 시간 차이를 서비스 전체 속도 향상률로 일반화하지 않는다.
- 검색 개선은 확인했지만 전체 10분 이상 분석이 얼마나 빨라졌는지는 새 유료 분석을 실행하지 않아 미측정이다.
- 미래 자료는 수정 전에도 최종 결과에서 제거됐다. 이번 수정의 핵심은 미래 후보 때문에 놓치던 유효 과거 자료를 검색 전에 확보하는 것이다.

### 주장–인용의 표본 검토에서 남은 문제

첫 라운드 주장 6개를 별도로 읽어 다음을 확인했다.

1. **시간 범위:** 6월 보고서의 2분기 전망을 10월 시점의 향후 1~4주 가설에 사용한다. 가설이라는 조건은 있지만 그 기간을 직접 뒷받침할 새 자료가 부족하다.
2. **인용 범위:** 자사주 취득 수량은 연결된 원문에 존재하지만 선택한 인용문은 공시 제목뿐이다. 사용자가 인용문만 보고는 핵심 수량을 확인할 수 없다.
3. **수치 근거:** FCF·희석률 수치는 공통 금융 입력에 있지만 선택한 인용은 현재 주가와 매출/자산 표다. FCF 계산 결과를 직접 인용하지 않아 주장의 근거 연결이 약하다.
4. **자료 날짜 형식:** DART 자료에 `YYYYMMDD` 형태의 날짜가 남아 있다. 기간을 비교하는 코드와 화면에서 쓰는 ISO 날짜로 일관되게 정규화하는 후속 작업이 필요하다.

따라서 ‘인용 연결 오류 0’은 **할루시네이션 0%나 투자 가설의 정확성 100%가 아니다.** 다음 품질 개선은 숫자·기간·주장과 직접 맞는 인용문 선택, 근거 부족 표시, 같은 자료를 반복하는 토론의 실질적 새 정보 평가다. 이번 수정으로 이미 생성된 결과를 다시 쓰거나 재게시하지 않았다.

## 5. 남은 적용·검증

- 운영 DB 형식 제약은 미적용이다. `CHECK ... NOT VALID`도 향후 UPDATE에는 적용되므로, 기존 불량 행의 비공개 전환까지 막힐 수 있다. 적용 전 `valid_discussion_result(payload)`가 거짓인 행의 ID·개수를 확인하고 정리·철회 방법을 정해야 한다.
- 기존/신규 DB SQL 함수는 정적으로 대조했지만 실제 PostgreSQL에서 실행하지 않았다.
- 다른 기업·새 문서·날짜 미상·정답 없음·반대 증거를 포함한 정답 세트를 확대해야 한다.
- 전체 AI 호출의 단계 시간·토큰·재시도·비용과 생성 답변의 독립적 의미 평가는 남아 있다.
- 북마크·화면 이동·목록 갱신·사용자 저장 총량·업로드 중복·공식 공개 철회 일관성은 사용자 요청에 따라 이번 단계에서 보류했다.
