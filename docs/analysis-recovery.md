# 분석 입력 및 실패 복구

## 입력과 출력
토론에 가격 시계열 전체를 전달하던 경로를 기존 build_regime_context 요약으로 교체했습니다. 원본 시계열은 결과와 차트에 유지합니다. 2026-10-14 저장 자료의 국면 입력은 로컬 토크나이저 계산으로 162873에서 6337토큰으로 줄어듭니다. 새 입력의 실제 API 사용량은 추가 유료 검증하지 않았습니다.

토론자와 중재자는 공통 구조화 응답 함수를 사용합니다. 출력은 4000토큰에서 시작하고 incomplete 사유가 max_output_tokens일 때만 8000으로 늘립니다. 출력 한도에 도달한 두 번째 응답은 더 반복하지 않습니다. 통신·타임아웃·5xx·일시적 429는 지수 대기 후 최대 총 3회 시도합니다. 인증·권한·insufficient_quota는 즉시 중단합니다. 잘못된 JSON도 총 시도 횟수 안에서만 재시도합니다. SDK 중첩 재시도는 끕니다.

자동 분석의 response-metrics 폴더에는 단계 이름·상태·중단 이유·입출력 및 추론 토큰·오류 종류와 HTTP 상태만 저장합니다. 키·프롬프트·응답 본문은 진단 기록에 포함하지 않습니다.

## 로컬 단계 복구
자동 삼성전자 분석은 RecoverableDebateWorkflow로 기존 워크플로를 재사용합니다. 수집·역사 자료·국면 분석·최초 상승 및 하락 분석·심리·영상·탐색 결과를 단계별로 저장하고, 토론 의제와 라운드별 발언·검토·최종 요약도 저장합니다. 실패한 호출의 결과는 저장하지 않습니다. 같은 입력 해시의 완료 단계는 재사용합니다.

체크포인트는 기존 Windows 사용자 MarketCouncil/daily의 날짜별 analysis JSON 파일이며 로컬 원문·분석 결과를 포함할 수 있습니다. 클라우드에 업로드하거나 패키지에 넣지 않습니다. 이 파일은 진단 수치 파일과 다릅니다. 날짜·기업·모델·토론 코드 및 프롬프트 서명으로 범위를 검증합니다. 불일치나 손상은 조용히 삭제하지 않고 실행을 중단합니다. 원격 생성 직후 프로세스 종료나 디스크 저장 실패가 발생하면 그 호출은 복구 기록에 남지 않을 수 있습니다.

하루 자동 분석 시도는 복구를 포함해 최대 2회입니다. 이후 수동 확인이 필요합니다. 게시만 실패하면 기존 JSON 재게시 흐름을 유지합니다. 공식 게시가 이미 있으면 유료 분석 없이 종료합니다. 일반 수동 PC 및 CLI 분석에는 단계 복구를 연결하지 않았으며 기존 desktop 0.4.0 바이너리에도 포함되지 않습니다.

## 검증 범위
모의 응답과 오류로 출력 한도·재시도·인증 및 잔액 중단·메타데이터 개인정보 제외·입력별 단계 재사용·실패 단계 재개·라운드 분리·하루 최대 2회와 기존 토론 종료 조건을 검증합니다. 이번 변경 후 새 유료 분석이나 새 공식 게시를 실행하지 않았습니다. 과거 최초 실패 원인은 상세 기록이 없어 확정하지 못했으며 이번 변경은 확인된 입력 낭비와 출력 제한·복구 취약점을 개선합니다.
