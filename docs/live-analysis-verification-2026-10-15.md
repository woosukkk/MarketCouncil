## 1. 실행 조건과 측정 범위

- 시작 시점에 커밋된 소스를 별도 폴더로 추출해 실행했다. 결과 폴더의 source-version.txt에 정확한 소스 식별자를 보관한다.
- 작업 디렉터리는 기존 Chroma 자료가 있는 C:/MarketCouncil을 유지했다. CHROMA_MODE=local, 삼성전자 티커, 자동 업로드 false를 명시했다.
- 새 검증 전용 체크포인트로 시작했다. 두 번째 프로세스는 동일 체크포인트로 같은 분석을 복구했으며 다른 기업이나 새 전체 분석을 실행하지 않았다.
- 기존 BGE-M3 캐시를 오프라인으로 사용하고 OMP/MKL 스레드를 4로 설정했다. Docker의 기존 SearXNG가 실행 중이었다. 색인을 재생성·삭제하지 않았다.
- Windows / Python 3.11.9 / 논리 CPU 12개. 사전 점검 시 남은 RAM은 약 0.8GiB로 다른 앱이 실행 중인 환경이었다.
- API 계측은 현재 경로의 동기 Responses.create 전체를 감쌌다. 공유 구조화 helper의 일부 기록만 합산하지 않았으며 같은 응답을 두 번 더하지 않았다.
- 비스트리밍 논리 호출 시간·상태·응답 모델·입력/캐시/출력/추론 토큰만 별도 기록했다. 프롬프트·응답 원문·키는 계측 JSON에 넣지 않았다.
- 실제 생성 결과·체크포인트·오류 상세는 로컬 Git 제외 폴더에만 있다. GitHub 기록에는 집계와 원인만 남긴다.

### 메모리 측정의 주의점

초기 실행 중 관측한 private/commit 메모리 최고치는 약 3.31GiB였다. 이는 실행 중 읽은 스냅샷의 누적 값이며 최종 최고치로 보증하지 않는다. RSS는 당시 물리 메모리에 올라온 양으로, 가상/commit 메모리와 다르다. 기존 Docker/WSL·브라우저·운영체제의 메모리는 분석 프로세스 RSS에 포함하지 않았다. 이 한 번의 실행만으로 최소 PC 사양이나 서버 메모리 규격을 확정하지 않는다.

사용 모델은 gpt-5-mini의 응답 스냅샷 gpt-5-mini-2025-08-07이었다. 공식 Standard 단가(100만 토큰당 입력 $0.25, 캐시 $0.025, 출력 $2.00)를 적용했다. 캐시는 입력에, 추론은 출력에 포함되므로 중복 가산하지 않았다. [OpenAI 모델 가격](https://developers.openai.com/api/docs/models/gpt-5-mini)

이는 계정 청구서가 아닌 **관측 사용량 기반 추정**이다. 잔액 소진 실패에는 usage가 없었고 해당 요청의 서버 청구량은 클라이언트에서 확인할 수 없다. SDK 내부의 물리 HTTP 재시도 횟수도 논리 호출 수에 포함해 셀 수 없다. 세금·환율·크레딧 조정·별도 서비스 요금은 계산하지 않았다. 이번 웹 검색은 SearXNG 경로였으며 응답에서 OpenAI 검색 도구 사용은 발견되지 않았다.

토론·중재 과정에서 같은 근거가 반복 전달되어 입력량이 컸다. 캐시 입력 0은 관측 사실이며 그 원인을 이번 계측만으로 확정하지 않는다. 다음 성능 후보는 필요한 근거 선별과 공통 입력의 고정된 앞부분 배치다. 캐시 재사용은 같은 prefix가 필요하므로 변경 내용은 뒤에 두는 방식을 비교할 수 있다. 실제 절감률은 같은 입력의 별도 비교가 필요하다. [OpenAI Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)

## 4. 답변·근거 품질

### 형식·인용 존재

- Python 결과 형식 검사 통과.
- 근거 카탈로그 159개 출처 / 791개 인용 후보.
- 2라운드, 양측 발언별 쟁점 12개, 채택된 인용 36회 / 고유 인용 9개.
- 36개 모두 선택 ID와 실제 원문이 연결됐다.
- 원래 잘못된 출처·인용 쌍 1회는 검사기가 제거하고 citation_errors에 남겼다. 이 건을 정상 인용으로 세지 않았다.
- 자동 수치 경고 8개, 해당 단위 숫자 없음 4개. 이번 범위의 날짜 미상·미래·오래된 전망 규칙 경고는 없었다. 경고 없음이 최신성·의미 적합성을 증명하지는 않는다.
- 수집된 가격·재무 통화는 모두 KRW였다. 통화가 실제로 분리 수집되는 것을 확인했다.

### 12개 발언의 수동 대조 요약

Codex가 저장된 원문·금융 입력과 12개 발언을 대조했다. 별도 유료 AI 심사 호출이나 독립 전문가 정답 판정은 아니다.

| 쟁점 | 양측·두 라운드에서 확인한 상태 |
|---|---|
| 반도체 수요·가격 시나리오 | 가정·자료 부재를 인정한다. 다만 선택한 웹 인용은 로고·본문 이동 링크여서 기사 주장에 대한 직접 지지가 부족하다. 숫자 경고가 없던 사례에도 의미 문제가 남는다. |
| 자사주 계획·반응 | 계획과 실제 집행을 구분한다. 수량·금액 자체는 전체 출처 본문에 있으나 실제 선택한 인용은 매수 방법·표 제목으로 직접 수치를 증명하지 못한다. 일부 가격 반응 수치도 선택 인용으로 확인되지 않는다. 거짓으로 확정한 것은 아니다. |
| FCF·재무 완충력 | FCF·부채비율의 직접 인용은 제공됐다. 일부 금액의 소수 표시 편차와 발행 주식 수 변화 인용 선택 누락이 반복된다. 발행 주식 수 변화와 EPS 희석률을 구분하고 조건부 가설을 유지한 점은 적절하다. |

8개 숫자 경고는 4개 자사주 관련 발언과 4개 금융 관련 발언에 나타났다. 작은 표시 편차와 인용 누락이 겹치므로 이를 잘못된 사실 8개, 정확도, 할루시네이션율로 바꾸지 않는다.

### 최종 중재·요약

제목·lead·summary는 1~4주 직접 자료 부족과 주요 쟁점 미해결을 유지했고 단기 매매 방향을 확정하지 않았다. 문제 수치를 그대로 최종 합의에 올리지 않고 FCF·부채비율을 적절히 반올림했으며 자사주도 취득 계획으로 구분했다.

다만 최종 상태는 OPEN 1개 / CONTESTED 2개로, 자료가 없어 판단할 수 없는 UNKNOWN과 입장 충돌을 엄격하게 구분하지 않았다. 최종 요약은 부분 충족으로 평가한다.

이전 저장 결과의 첫 라운드 6개도 같은 기준으로 대조했으나, 새 실행은 자료·의제·라운드가 다르다. 정답 세트 기반의 전후 비교나 개선율로 제시하지 않는다. 현재 숫자·ID 존재 검사만으로 전체 답변 품질 통과를 선언할 수 없다.

## 5. 이번에 확정한 추가 원인

### A. API 잔액 소진의 불필요한 재시도 — 소스 수정 완료

실제 오류는 HTTP 429 / code=credit_balance_exhausted였다. 속도 제한이 아니라 API 잔액 소진이었다. 기존 코드는 insufficient_quota만 재시도 불가로 처리해 새 코드를 일시적 오류로 보고 3회 재시도했으며 진단 코드도 남기지 않았다.

- tools/structured_response.py: 첫 실패에서 중단하고 안전한 오류 코드 보존.
- desktop/daily_official.py: 래핑된 원인의 코드도 보존.
- 회귀 3개 추가: 잔액 소진 1회 중단, 정상 속도 제한의 재시도 유지, 비밀 없는 진단 기록.
- Python 123개 + 별도 함수형 7개 **총 130개 통과**. 커밋된 소스만 추출한 폴더에서도 동일 통과.
- 실제 복구는 시작 당시의 소스 스냅샷을 유지해 체크포인트를 재사용했다. 복구 계측기에 잔액 오류 즉시 중단 가드를 넣었고, 추가 API 호출은 요약·읽기 안내 2회뿐이었다. 새 잔액 오류 처리 코드는 별도 회귀 검증했다.
- 이번 실행의 직접 실패 원인은 확인했지만 과거 자동 게시 최초 실패 원인까지 소급 확정한 것은 아니다.

### B. 웹 본문 앞부분 절단 — 확인 완료, 수정 남음

캐시의 해당 페이지 두 개만 읽기 전용으로 확인했다. 원본 본문이 수집됐는데 분석 전달 전에 잘렸다.

| 출처 | 캐시 마크다운 | 실제 전달 | 본문 관련 문장 시작 |
|---|---:|---:|---:|
| WEB-007 | 42,966자 | 앞 1,200자 | 약 3,551자 이후 |
| WEB-012 | 17,421자 | 앞 1,200자 | 약 1,826자 이후 |

`tools/crawl4ai_extractor.py`는 전체 마크다운을 본문 정제 없이 앞 1,200자로 자른다. `tools/evidence_catalog.py`는 길이 조건을 만족하는 첫 16개 문장을 선택하므로 두 페이지의 후보 16개씩이 전부 마크다운 링크였다. 링크도 본문에 존재하므로 존재 검사에서는 참이 된다.

다음 수정은 **본문 선택·정제 후 길이 제한 → 메뉴·로고·이동 링크 제외·중복 제거 → 본문 미확보 시 근거 부족** 순서가 적절하다. 길이 제한만 늘리는 것으로는 충분하지 않다. 이 변경이나 재생성은 이번 실행에서 적용하지 않았다.

## 6. 남은 우선순위

1. 웹 본문 추출과 인용 후보 정제를 먼저 수정하고 긴 메뉴·본문 없는 페이지를 합성 입력으로 검증.
2. 금융 지표·단위·기간과 인용 선택을 더 엄격히 연결하고 숫자 표시 변환을 줄임.
